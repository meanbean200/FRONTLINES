Engineers could walk to a more distant branch rather than resume the face beside them. `EngineerSystem.workFaces` now exposes unfinished faces in distance order; Resume tries reachable faces/jobs and ignores already-complete ends. This does not dig remotely or alter completed geometry.
2. **Engineer travel used idle animation and idle energy cost.** The new `moving to work front` and `moving along work front` actions were missing from older render/needs string checks. A shared `SoldierActions.isWalkingAction` recognizes these actions without renaming saved state. Walking legs and travel exertion now agree; digging stays stationary.
3. **Direct reassignment between separate trenches was rejected.** The live completed-T playthrough selected Rifle 01, clicked the empty network, and received the unreachable-approach message despite clear ground. The assignment preflight assumed anyone already in a trench could only use a connected corridor. Explicit reassignment now validates the complete journey before releasing the old assignment, creates a temporary physical travel duty, exits locally, crosses checked ground, and enters the reachable target floor. Normal duties resume only after arrival. Routine supply errands still cannot jump between disconnected trenches.
4. **Interruption hardening and clearer status.** Hold cancels relocation; alert scheduling does not repeatedly steal travelling troops. Geometry changes revalidate affected travel. Save validation includes temporary exit/entry coordinates. A regression also exposed immediate authorized withdrawal routing from the wrong network; it now uses the actual source exit. The roster detail and world flag say **Relocating** while that trip is pending, rather than prematurely saying Defending. No label hiding, debounce, or fade was restored.
